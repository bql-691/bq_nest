# 代码撰写规范

本规范规定本仓库新代码怎么放、怎么命名、怎么接进模块。业务数据流见 [项目架构](./项目架构.md)。前端的对应规范在 `bq_react` 的 `doc/项目文档/代码撰写规范.md`。两边都用小写蛇形文件名、帕斯卡类名、小驼峰方法名，以及 `domain`、`application`、`infra`、`presentation` 四层。

## 环境变量

环境文件放在仓库根目录。`main.ts` 首先导入 `dotenv/config`。示例见 `.env.example`。

| 变量             | 作用                                                         |
| ---------------- | ------------------------------------------------------------ |
| `PORT`           | 监听端口。缺省 `3000`                                        |
| `DATABASE_URL`   | SQLite 文件，例如 `file:./dev.db`                            |
| `JWT_SECRET`     | 签发和校验访问凭证的密钥                                     |
| `JWT_EXPIRES_IN` | 凭证有效期。缺省 `7d`                                        |
| `CORS_ORIGIN`    | 允许的前端来源，多个用逗号分隔。缺省 `http://localhost:5173` |

密钥只放在 `.env`。`.env` 不提交。业务代码通过 `ConfigService` 或 `process.env` 读取，并在使用处处理缺省值。`PrismaService` 对 `DATABASE_URL` 使用 `getOrThrow`。`JwtModule` 对 `JWT_SECRET` 使用 `getOrThrow`。

## 目录与分层

`src/app` 放全库能力，不放业务用例。`src/features/<name>` 放一个功能模块。

| 层             | 放置                 | 可以依赖                                                         |
| -------------- | -------------------- | ---------------------------------------------------------------- |
| `domain`       | 实体、端口、领域方法 | 本模块 `domain`，以及 `src/app/domain` 的 `Actor`、`DomainError` |
| `application`  | 用例                 | 本模块 `domain`，以及 `src/app/domain`                           |
| `infra`        | 端口的实现           | 本模块 `domain`，以及 `src/app/prisma`                           |
| `presentation` | Controller、DTO      | 本模块 `application`，以及 `src/app/auth`                        |

`domain` 不引用 `@nestjs/common` 的 Controller，也不引用 Prisma。没有内容的层不建空目录。

聚合根是外部唯一可以修改的实体。项目规则写在 `Project` 和 `projectFromClient` 上：路径里的 id 必须与报文 id 一致，`ownerId` 由服务端写入，名称去掉首尾空白，缺少的文档按空文档处理。Controller 不改这些字段。

仓储接口只表达取出和保存，不出现 SQL。接口的返回值是领域对象。登录返回 `{ token, user }`，`user` 的类型是 `PublicUser`。`passwordHash` 不出现在这个结果里。

`DomainError` 表示已经决定的业务失败。HTTP 状态和 `{ code, message, data }` 由 `src/app/http` 写出，用例不组装响应体。

## 文件命名

目录和文件用小写蛇形。

| 种类     | 形式                                        | 例子                                                 |
| -------- | ------------------------------------------- | ---------------------------------------------------- |
| 模块     | `*_module.ts`                               | `security_module.ts`                                 |
| 用例     | `*_application.ts`                          | `security_application.ts`                            |
| 实体     | 业务名文件                                  | `document.ts`、`user_entity.ts`、`project_entity.ts` |
| 抽象端口 | `i_` 前缀，或业务名抽象类                   | `i_user_repository.ts`、`password_hasher.ts`         |
| 仓储实现 | `*_repository.ts`，放在 `infra/persistence` | `prisma_user_repository.ts`                          |
| 控制器   | `*_controller.ts`                           | `auth_controller.ts`                                 |
| 入参     | `*_dto.ts`，放在 `presentation/dto`         | `login_dto.ts`                                       |
| 测试     | 与被测文件同目录，`*.spec.ts`               | `security_application.spec.ts`                       |

`Project` 的类名是业务名，文件仍是 `project_entity.ts`。`UserEntity` 的类名带 `Entity`。新增实体用业务名，类名不再加 `Entity`。

## 类与函数命名

类用帕斯卡命名。函数和方法用小驼峰。

| 种类       | 形式                    | 例子                                  |
| ---------- | ----------------------- | ------------------------------------- |
| 用例       | `名称Application`       | `SecurityApplication`                 |
| 控制器     | `名称Controller`        | `AuthController`、`ProjectController` |
| 仓储实现   | `名称Repository`        | `PrismaUserRepository`                |
| 端口       | 抽象类。仓储加 `I` 前缀 | `IUserRepository`、`PasswordHasher`   |
| 实体       | 业务名                  | `Project`、`Document`、`LineShape`    |
| 当前调用者 | `Actor`                 | `src/app/domain/actor.ts`             |
| 模块       | `名称Module`            | `SecurityModule`                      |

用例方法用动词：`register`、`login`、`me`、`list`、`get`、`save`。

## 依赖注入

全库没有手写的根容器。`AppModule` 引入各功能模块，Nest 按构造函数注入。

| 对象                        | 写法                                                |
| --------------------------- | --------------------------------------------------- |
| 用例、仓储、`PrismaService` | `@Injectable()`，并写入所在 `Module` 的 `providers` |
| 抽象端口                    | `{ provide: 端口, useClass: 实现 }`                 |
| 全局守卫                    | `{ provide: APP_GUARD, useClass: JwtAuthGuard }`    |
| 控制器                      | 写入 `controllers`，构造函数注入用例                |

端口只在功能模块里绑定一次。用例构造函数声明端口类型，不声明 Prisma 或 bcrypt。

```ts
providers: [
  SecurityApplication,
  { provide: IUserRepository, useClass: PrismaUserRepository },
  { provide: PasswordHasher, useClass: BcryptPasswordHasher },
  { provide: TokenIssuer, useClass: JwtTokenIssuer },
];
```

`@Injectable()` 的类在模块内默认是单例。用例和仓储保持这一个实例。不要在用例里 `new` 仓储。

## 功能模块

`src/features/<name>/<name>_module.ts` 声明本模块的 Controller、用例和端口绑定。它不写业务判断。

`SecurityModule` 还注册 `JwtModule`，并把 `JwtAuthGuard` 注册为 `APP_GUARD`。除标了 `@Public()` 的路由外，请求先经过这个守卫。守卫和用例都在这个模块里，直接注入 `IUserRepository`。模块同时 `exports` 这份端口，供其他模块在 `imports` 本模块后使用。

`ProjectModule` 把 `IProjectRepository` 绑到 `PrismaProjectRepository`。

`AppModule` 必须 import 这两个模块，路由才会挂上。

## import

本仓库是 ESM。相对导入写到文件，并带 `.js` 后缀，与运行时的输出一致。没有 `@/` 别名。

```ts
import { DomainError } from '../../../app/domain/domain_error.js';
import { SecurityApplication } from '../application/security_application.js';
```

类型使用 `import type`。功能模块可以引用 `src/app` 里标明给它用的类型。不引用另一个功能模块的 `infra`。

## 测试

用例的单元测试与用例放在同一目录，用内存里的端口替身，不启动 HTTP，也不连接开发库。文件名 `*_application.spec.ts`。

端到端测试在 `test/app.e2e-spec.ts`。它先执行 `prisma migrate deploy`，再启动 `AppModule`。配置见 `vitest.config.e2e.ts`。

`npm test` 跑单元测试。`npm run test:e2e` 跑端到端测试。`npm run lint` 检查 `src/` 和 `test/`。`npm run format:check` 按 Prettier 检查格式。提交前会先跑格式检查，再跑 lint。

## 新增功能模块

1. 在 `src/features/<name>/domain` 写实体和端口。端口是抽象类。
2. 在 `application` 写用例，并标 `@Injectable()`。失败时抛 `DomainError`。
3. 在 `infra` 写实现，标 `@Injectable()`。
4. 在 `presentation` 写 Controller。需要登录的路由使用 `@CurrentUser()`。公开路由加 `@Public()`。
5. 写 `<name>_module.ts`。`providers` 里用 `{ provide: 端口, useClass: 实现 }` 绑定。
6. 在 `src/app_module.ts` 的 `imports` 加入这个模块。
