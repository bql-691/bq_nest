## 模块先绑好端口

`src/features/security/security_module.ts` 把三个端口交给实现：

```ts
{ provide: IUserRepository, useClass: PrismaUserRepository },
{ provide: PasswordHasher, useClass: BcryptPasswordHasher },
{ provide: TokenIssuer, useClass: JwtTokenIssuer },
```

`AppModule` 导入 `SecurityModule` 之后，`POST /auth/login` 才会由 `AuthController` 处理。这里没有前端那种只做副作用的 `security.ts`。

## 控制器把入参交给用例

`AuthController.login` 标了 `@Public()`，所以这次请求不经过凭证校验。`@HttpCode(HttpStatus.OK)` 使 Nest 对 `POST` 返回 200，而不是 201。

`LoginDto` 先被全局 `ValidationPipe` 校验。通过后控制器调用：

```ts
return this.application.login(dto);
```

控制器不写口令比对，也不组装 `{ code, data, message }`。这层信封由 `ResponseInterceptor` 加上。

## 用例只依赖端口

`SecurityApplication.login` 不引用 Prisma 和 JWT。它调用 `IUserRepository.findByUsername`，再调用 `PasswordHasher.verify`。失败抛出 `DomainError(401, '用户名或密码错误')`。成功时调用 `TokenIssuer.issue`，并用 `user.toPublic()` 得到不含 `passwordHash` 的用户。

返回值是 `{ token, user }`。前端拿到的 `data` 就是这个对象。

## 实现负责数据库和凭证

`PrismaUserRepository.findByUsername` 按 `username` 查询，把行收成 `UserEntity`。`roles` 列是 JSON 字符串。

`BcryptPasswordHasher.verify` 调用 `bcrypt.compare`。`JwtTokenIssuer.issue` 把 `sub: user.id` 签进凭证。

## 下一次请求带上凭证

读取项目时，请求头带 `Authorization: Bearer <token>`。`JwtAuthGuard.canActivate` 没有看到 `@Public()`，就校验凭证，用 `sub` 调用 `findById`，并把 `Actor` 写入 `request.user`。

`ProjectController.get` 用 `@CurrentUser()` 接住这个 `Actor`，调用 `ProjectApplication.get`。用例按 id 取出 `Project`，再 `assertAccessible`。所有者或持有 `project:write` 的调用者得到 `plainProject` 的结果。其他人得到 404，消息是「项目不存在」。
