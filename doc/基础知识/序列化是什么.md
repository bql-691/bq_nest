# 序列化是什么

前端用 mobx-keystone 的 `getSnapshot` 和 `fromSnapshot` 保存实体。后端不使用这套库。实体是普通类，字段上的装饰器同时声明校验和 JSON 形状。两边约定同一份字段，不各写一套接口类型。

## 字段即形状

`class-validator` 决定值能不能接受。`class-transformer` 决定普通对象和类实例怎样互转。`Project`、`Document`、`LineShape`、`RectShape` 的字段写在类上。没有第二份 Zod 或 interface 再描述这些字段。

`JSON.stringify` 不会看 `@Exclude`。写出给前端或写入数据库的文档时，使用 `instanceToPlain`。读入时使用 `plainToInstance`，再 `validate`。

`ownerId` 标了 `@Exclude({ toPlainOnly: true })`。它留在服务端的 `Project` 上，`plainProject` 的结果里没有它。

## type 与模型名

多态靠字段 `type`。`Document.shapes` 的 `@Type` 使用判别属性 `type`，并打开 `keepDiscriminatorProperty`，这样转成普通对象后 `type` 仍在。

| `type`              | 类          |
| ------------------- | ----------- |
| `project/Project`   | `Project`   |
| `project/Document`  | `Document`  |
| `project/LineShape` | `LineShape` |
| `project/RectShape` | `RectShape` |

这些字符串目前与前端 `@model` 的名称相同。前端发出请求前会去掉 `$` 开头的字段，收回项目时再按自己的表把 `type` 还原成 `$modelType`。后端报文里不出现 `$modelType`。

旧的文档 JSON 若只有 `$modelType`，`asTypeRecord` 在 `plainToInstance` 之前把它抄到 `type`，并丢掉 `$` 开头的字段。

## 读入和写出

`projectFromClient` 处理 `PUT /projects/:id` 的报文。缺少 `document` 时补上 `{ type: 'project/Document', shapes: [] }`。校验失败把约束消息用 `'; '` 接起来，没有消息时用「项目数据无效」。

`projectFromRecord` 处理数据库行。`document` 列是 JSON 字符串，解析后再走 `asTypeRecord`。

`PrismaProjectRepository.save` 把 `instanceToPlain(project.document)` 存进 `document` 列。响应整份项目时用 `plainProject`。

## 登录入参

登录和注册不使用项目这套判别。`LoginDto` 和 `RegisterDto` 只声明自己的字段。全局 `ValidationPipe` 打开 `whitelist`，未声明的字段会被去掉。

不打开 `forbidNonWhitelisted`。报文里若仍带有 `$modelType` 或其他多余字段，登录不会因此变成 400。
